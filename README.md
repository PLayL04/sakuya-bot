# sakuya-bot

Discord-бот для одного сервера. Отправляет картинки по расписанию (например, «доброе утро» в 08:00).

## Установка

1. Создайте приложение на https://discord.com/developers/applications, во вкладке **Bot** получите токен
   и включите **Message Content Intent** (без него бот не видит текст сообщений и не запустится).
2. Пригласите бота: **OAuth2 → URL Generator**, scopes `bot` + `applications.commands`,
   права `Send Messages`, `Attach Files`, `View Channels`, `Read Message History`, `Add Reactions`.
3. Скопируйте `.env.example` в `.env` и заполните `DISCORD_TOKEN` и `GUILD_ID`.
   Остальное (роли управления, каналы, кулдауны, часовой пояс) настраивается уже на сервере — см. «Настройки».
4. Установите зависимости и запустите:

```bash
.venv\Scripts\pip install -r requirements.txt
```

```bash
.venv\Scripts\python bot.py
```

## Команды

Работают только у тех, кто управляет ботом: участники с правом «Управлять сервером» и с ролями из `admin_roles`
в настройках (см. ниже). Остальным бот ответит отказом.

Команды видны в списке `/` всем участникам, а доступ проверяет бот по `admin_roles`: чтобы дать роли управление
ботом, достаточно добавить её в настройки, больше ничего включать не нужно. Скрыть команды от обычных участников
можно вручную в Настройки сервера → Интеграции → бот — но тогда роли из `admin_roles` нужно разрешить там же,
иначе Discord не покажет команды и им.

| Команда | Что делает |
|---|---|
| `/schedule daily time:08:00 channel:#общий image:<файл>` | Каждый день (картинку можно загрузить) |
| `/schedule daily time:08:00 channel:#общий file:<имя>` | …или взять готовую из папки `img/` |
| `/schedule weekly weekday:Friday time:18:00 channel:#общий ...` | Каждую неделю в выбранный день |
| `/schedule monthly day:1 time:10:00 channel:#общий ...` | Каждый месяц в указанный день (31 → последний день месяца) |
| `/schedule yearly date:01.01 time:00:00 channel:#общий ...` | Каждый год в эту дату |
| `/schedule once date:01.01.2027 time:00:00 channel:#общий ...` | Один раз, после отправки расписание удаляется; `date:01.01` без года — ближайшее 1 января |
| `/schedule list` | Список расписаний |
| `/schedule edit id:<id> time:09:00` | Изменить время, канал, картинку, текст (`message:-` — убрать) или день |
| `/schedule pause id:<id>` / `/schedule resume id:<id>` | Приостановить и снова включить (пропущенное за паузу не отправляется) |
| `/schedule remove id:<id>` | Удалить расписание |
| `/schedule test id:<id>` | Отправить прямо сейчас (проверка) |
| `/reaction add word:кот emoji:🐱` | Реакция на любую форму слова: «кот», «кота», «котами» |
| `/reaction add word:кот emoji:🐱 match:Точное слово` | Только ровно «кот» |
| `/reaction add word:кот emoji:🐱 match:Часть слова` | Любое слово, содержащее «кот»: «котик», «котлета», «скот» |
| `/reaction add word:привет emoji:🇰 🇴 🇹` | Несколько эмодзи — бот ставит их по порядку, получается комбинация |
| `/reaction add word:кот image:<файл>` | Отвечать на сообщение картинкой или GIF (без пинга автора) |
| `/reaction add word:кот emoji:🐱 file:<имя>` | Реакция и ответ картинкой из папки `img/` |
| `/reaction list` | Список правил реакций |
| `/reaction edit id:<id> emoji:🐶` | Изменить слово, эмодзи (`-` — убрать), способ поиска или картинку (`file:-` — убрать) |
| `/reaction pause id:<id>` / `/reaction resume id:<id>` | Временно выключить правило и снова включить |
| `/reaction remove id:<id>` | Удалить правило |
| `/settings show` | Текущие настройки бота |
| `/settings download` | Скачать файл настроек |
| `/settings upload file:<файл>` | Загрузить исправленный файл настроек |

Формы слов определяются словарём [pymorphy3](https://github.com/no-plagiarism/pymorphy3): «люди» найдётся по правилу «человек»,
«бежал» — по «бежать». Уменьшительные слова считаются отдельными: «котик» по правилу «кот» не сработает.
Английские слова обрабатываются через [simplemma](https://github.com/adbar/simplemma): правило «cat» сработает на «cats»,
«go» — на «went», «mouse» — на «mice».
Работает и для фраз: правило «доброе утро» сработает на «доброго утра», «good morning» — на «good mornings».

Правило может ставить эмодзи, отвечать картинкой (PNG, JPG, GIF, WEBP) или делать и то и другое.
Эмодзи можно указать несколько (до 20 — больше разных реакций Discord не ставит): бот поставит их по порядку,
так из букв 🇦–🇿, цифр 1️⃣ и обычных эмодзи складываются слова и комбинации. Буквы-флажки разделяйте пробелом:
две такие буквы подряд Discord и Unicode считают флагом страны (🇷 + 🇺 = 🇷🇺). Одинаковые эмодзи в одном правиле
повторять нельзя — одну и ту же реакцию на сообщение можно поставить только один раз. Ответ приходит
без пинга автора; одно правило отвечает картинкой в одном канале не чаще раза в минуту (`image_cooldown`
в настройках), чтобы не заспамить чат. Если сработало несколько правил, все картинки придут одним сообщением.

На пинг (упоминание бота, его роли или ответ с пингом) бот ставит эмодзи сервера (`ping_emoji` в настройках, по умолчанию `:MadelineAlo:`) — так легко проверить,
что он онлайн. Эмодзи ищется по имени; если его на сервере нет, бот ставит 💩 и пишет предупреждение в лог.

## Латте-арт: `!кофе`

Доступно всем участникам. Бот рисует картинку пенкой на кофе в чашке из шаблона `template/coffee.png` и отвечает готовым изображением.

- `!кофе` **ответом** на сообщение с картинкой — берёт картинку из него;
- `!кофе` с **приложенной** картинкой — берёт её;
- просто `!кофе` — берёт **последнюю картинку выше** в канале (до 50 сообщений назад).

Подходят вложения, картинки по ссылкам, стикеры, **гифки и видео** (в ответ придёт анимация, см. ниже).
Также работают `!coffee` и `!латте`.
Один участник может вызывать команду раз в 15 секунд (`cooldown` в настройках; неудачная попытка без картинки
не считается). Чтобы развлекательные команды (`!кофе`, `!пиво`, `!explode`, `!implode`, `!музей`, `!цитата`) работали
только в определённых каналах, перечислите их ID в `channels` в настройках: в остальных каналах бот их молча игнорирует
(ветки внутри разрешённых каналов тоже подходят). Пустой список — работают везде.

### Шаблоны и их настройки

Шаблон бывает двух видов:
- **плоская заливка** — место под эффект залито ровным ярким зелёным (как `coffee.png`, `beer.jpg`) или сделано прозрачным;
- **перекрашенное фото** — настоящая фотография, где жидкость перекрашена в зелёный, но сохранены капли, блики и тени
  (как `beer2.jpg`). Для такого шаблона рядом кладётся файл настроек с тем же именем — `beer2.json`:

```json
{
  "key": "hue",
  "shading": 1.0,
  "beer": {"walls": "straight", "bubbles": false, "glass": false}
}
```

- `key`: `"hue"` — вырез ищется по оттенку, поэтому тёмные и оливковые участки (стенки) тоже попадают в вырез;
  по умолчанию `"chroma"` — для плоской заливки;
- `shading`: перенос освещения шаблона — капли, свечение и тени шаблона ложатся поверх эффекта
  (общий шаг для `!кофе` и `!пиво`); `0` или нет ключа — не переносить;
- `beer`: настройки пива — `walls` (`"straight"` — прямые стенки, `"shaped"` — фигурные, по умолчанию),
  `bubbles` и `glass` — рисовать ли свои пузырьки и блики стекла (у фото-шаблона они уже есть).

Без файла настроек всё работает как для плоской заливки. Размеры эффекта (рябь, пузырьки) считаются от ширины бокала,
поэтому шаблон может быть любого масштаба.

Картинка подгоняется под вырез «с заполнением»: масштабируется так, чтобы закрыть весь круг, лишнее по краям обрезается
(центр чуть смещён вверх — там обычно лица). Чтобы заменить шаблон, положите вместо `template/coffee.png` картинку,
где место под рисунок залито ярко-зелёным или сделано прозрачным, и перезапустите бота.

### Анимации и видео

Если в сообщении GIF, анимированный PNG/WebP, видео (mp4, webm, mov) или гифка из Tenor/Giphy, `!кофе`, `!пиво`,
`!explode`, `!implode` и `!музей` отвечают анимацией в GIF:
- берутся первые 6 секунд, не больше 15 кадров в секунду; результат — до 480 px по большей стороне;
- вырез, освещение и всё, что зависит только от шаблона (у пива — линза, рябь, пузырьки), считается один раз,
  а для каждого кадра — только сама картинка;
- палитра GIF одна на всю анимацию: неподвижный фон хранится один раз, файл в разы меньше;
- результат подгоняется под лимит файла сервера: если не влезает — сначала без дизеринга, потом кадры уменьшаются;
- одновременно обрабатывается одна картинка, остальные ждут в очереди (видно «печатает…»).

Видео читается библиотекой PyAV (`av` в `requirements.txt`, ставится вместе с ffmpeg внутри). Файлы — до 25 МБ.
Ориентир по скорости на домашнем ПК: GIF на 8 кадров — около 0,5–0,8 с, 6 секунд анимации — 3–6 с.

## Пиво: `!пиво`

Доступно всем участникам. Картинка оказывается **внутри** бокала из шаблона `template/beer.jpg` — видна сквозь стекло и пиво.
Картинку команда находит так же, как `!кофе` (ответ, вложение или последняя выше). Также работает `!beer`.

Как получается эффект:
- бокал работает как линза: центр картинки увеличен, к стенкам сжат, плюс лёгкая рябь;
- цвет — по закону Бугера — Ламберта — Бера: свет гаснет в пиве, синий сильнее всего, поэтому всё янтарное,
  темнее в центре бокала (там толще слой) и книзу;
- предмет на картинке загораживает свет, идущий сквозь пиво, поэтому он темнее чистого пива вокруг; края картинки
  растушёваны, а у стикеров по краю идёт тёмный контур, чтобы силуэт читался;
- пузырьки поднимаются цепочками и растут к поверхности, сверху — блики стекла и переход к пене.

Цвет пива задаётся `Palette` в `sakuya_bot/beer/effect.py`. Значения подобраны программой под цвет пива с исходной
картинки шаблона (до замены на зелёный), только светлее и золотистее: под пеной пиво темнее (тень от шапки),
толстое стеклянное дно светлое.

Картинка масштабируется между «заполнить» и «вписать»: высокий бокал не отрезает у широких картинок почти всё,
а свободное место остаётся чистым пивом. Каналы — те же, что у `!кофе` (`channels` в настройках).
Кулдаун — тот же (`cooldown`), но считается отдельно от `!кофе`.

## Искажения: `!explode` и `!implode`

Доступно всем участникам. Команды меняют саму картинку, без шаблона:

| Команда | Что делает |
|---|---|
| `!explode` | «Рыбий глаз»: центр раздут (примерно в 3,3 раза), к краям картинка сжимается |
| `!implode` | Вдавливание: центр уменьшен (в 2,5 раза) и втянут внутрь, края растянуты |

Картинку команды находят так же, как `!кофе` (ответ, вложение или последняя выше); гифки и видео — анимацией (см. выше).
Каналы и кулдаун — те же, что у `!кофе`; кулдаун считается для каждой команды отдельно.

Искажение радиальное: каждый пиксель берёт цвет с того же луча от центра, но с другого расстояния
(функция `radial_distort` в `sakuya_bot/distort/effect.py`, NumPy). Действует внутри вписанного в картинку эллипса
и плавно сходит на нет к его краю, так что шва нет, а углы картинки остаются как были. Сила задаётся константами
`EXPLODE` и `IMPLODE` — это масштаб в центре (меньше 1 — увеличение, больше 1 — уменьшение). Результат — PNG до 1280 px
по большей стороне (анимация — до 480 px); прозрачный фон заливается чёрным.

## Музей: `!музей`

Доступно всем участникам. Картинка вешается в раму на стене музея из шаблона `template/museum.jpg`: зелёный вырез
заменяется картинкой, больше ничего с ней не делается. Также работает `!museum`.
Картинку команда находит так же, как `!кофе` (ответ, вложение или последняя выше); гифки и видео — анимацией (см. выше).
Каналы и кулдаун — те же, что у `!кофе`.

Главное отличие от `!кофе` и `!пиво` — картинка **не обрезается**: она вписывается в раму целиком («вписать», а не
«заполнить»), а свободное место по краям и прозрачный фон стикеров заливаются светлым паспарту (`MAT_COLOR`
в `sakuya_bot/museum/effect.py`). Люди перед картиной остаются на переднем плане — они не зелёные и в вырез не попадают.
Результат — JPEG в размере шаблона.

## Цитаты: `!цитата`

Доступно всем участникам. Бот отправляет в канал случайный отрывок из текстов в папке `quotes/` (рядом с `bot.py`;
другую папку можно указать в `QUOTES_DIR` в `.env`). Также работает `!quote`.
Каналы и кулдаун — те же, что у `!кофе` (если текстов нет, попытка не считается).

Тексты — обычные файлы `*.txt` в UTF-8 (cp1251 из старого Блокнота тоже читается). Каждый файл — один источник:
- подпись под цитатой — первая строка вида `# Автор — «Название»`, а если её нет — имя файла;
- абзацы разделяются пустой строкой, переносы строк внутри абзаца склеиваются (подходит для текстов с переносами
  по ширине); строка, начинающаяся с тире, — новая реплика диалога. Если пустых строк в файле нет совсем,
  абзац — каждая строка;
- короткие строки без точки в конце («Глава 2») считаются заголовками и в цитаты не попадают.

Файлы можно добавлять и менять на ходу — бот перечитает их при следующем вызове. Файл выбирается пропорционально
размеру, так что каждый кусок текста выпадает одинаково часто. Папка `quotes/` в `.gitignore`: у каждой копии бота свои тексты.

Длина цитаты каждый раз разная: примерно в 40% случаев — короткая (одно-два предложения, до 200 символов),
в 40% — средняя (несколько предложений, 200–600), в 20% — длинная (с начала абзаца, один или несколько абзацев,
до 1600). Цитата всегда состоит из целых предложений: текст делится по `.`, `!`, `?` и `…`, за которыми идёт заглавная
буква; инициалы и сокращения («А. С. Пушкин», «т. е.», «1999 г.») предложение не разрывают.

Сообщение оформлено так: каждый абзац — строкой блока цитаты `>`, одно короткое предложение — жирным,
внизу мелким шрифтом курсивом подпись `-# — *источник*`. Символы разметки из текста (`*`, `_`, `` ` `` и т. п.)
экранируются, упоминания (`@everyone`) не пингуют. Сообщение всегда укладывается в лимит Discord в 2000 символов:
если после экранирования не влезает, с конца убираются целые предложения. Пороги длины — `LENGTHS`
в `sakuya_bot/quotes/picker.py`.

## Настройки

Всё, что может понадобиться поменять модерации, хранится в файле `data/settings.toml`, а не в `.env`:

| Ключ | Что задаёт | По умолчанию |
|---|---|---|
| `[access] admin_roles` | Роли, участники с которыми управляют ботом (`/schedule`, `/reaction`, `/settings`) | `[]` |
| `[fun] channels` | Каналы развлекательных команд; `[]` — все каналы | `[]` |
| `[fun] cooldown` | Кулдаун развлекательных команд на участника, секунд; `0` — без ограничения | `15` |
| `[reactions] image_cooldown` | Как часто одно правило отвечает картинкой в канале, секунд | `60` |
| `[reactions] ping_emoji` | Имя эмодзи сервера, которым бот отвечает на пинг | `"MadelineAlo"` |
| `[schedule] timezone` | Часовой пояс для времени в `/schedule` и в логах | `"Europe/Moscow"` |
| `[logs] channel` | Канал логов для модераторов (см. ниже); `0` — не писать | `0` |

Менять настройки можно прямо в Discord, доступ к серверу с ботом не нужен:
1. `/settings download` — бот пришлёт текущий файл (подсказки к каждому ключу — в комментариях `#`);
2. исправить его в любом текстовом редакторе;
3. `/settings upload file:<файл>` — бот проверит файл и ответит, что изменилось. Если в файле ошибка (опечатка в ключе,
   не число вместо числа, неизвестный часовой пояс), ничего не меняется, а бот напишет, что не так. Роли, каналы
   и эмодзи, которых нет на сервере, не ошибка, но бот о них предупредит.

Настройки действуют сразу, без перезапуска. Файл можно поправить и прямо на сервере с ботом — бот перечитает его
в течение 30 секунд (если в нём ошибка — останутся прежние настройки, а в логе будет запись об ошибке).

Участники с правом «Управлять сервером» управляют ботом всегда, даже если `admin_roles` пуст или роль удалили, —
так доступ к боту не потерять. Загрузить файл, после которого у самого загружающего не останется доступа, бот не даст.

При первом запуске файл создаётся сам: роли, каналы и часовой пояс берутся из старых ключей `ADMIN_ROLE_ID`,
`FUN_CHANNEL_ID` и `TIMEZONE` в `.env`, если они там есть. Дальше эти ключи `.env` не читаются.

Когда в новой версии бота появляются настройки (как `[logs] channel`), бот при запуске сам дописывает их в файл
со значениями по умолчанию и подсказками — остальной текст и комментарии модераторов не меняются.

### Канал логов

Если задать `[logs] channel`, бот пишет в этот канал коротко и без пингов:
- кто создал, изменил (было → стало), поставил на паузу, включил или удалил правило реакции и расписание;
- кто поменял настройки и что именно (и изменения, сделанные прямо в файле на сервере);
- какое расписание не удалось отправить и почему (нет прав, канала, файла), и пропущенные разовые расписания.

Полный журнал по-прежнему пишется в `logs/` на сервере. Боту в канале логов нужны права «Просматривать канал»
и «Отправлять сообщения» — если их нет, `/settings show` и `/settings upload` предупредят.

### Проверки при создании расписания

Бот сразу проверяет, что в выбранном канале у него есть права «Просматривать канал», «Отправлять сообщения»
и «Прикреплять файлы», и что картинка влезает в лимит файла сервера. Иначе расписание не создаётся, и бот пишет,
чего не хватает, — ошибка не всплывёт только в момент отправки.

### Картинки в `img/`

Картинки, загруженные через `/schedule` и `/reaction`, бот удаляет сам, когда они больше не нужны ни одному
правилу и расписанию (правило удалили, картинку заменили, разовое расписание отправилось). Список таких картинок —
в `data/uploads.json`. Файлы, положенные в `img/` вручную, бот не удаляет никогда.

Данные хранятся в `data/` (`settings.toml`, `schedules.json`, `reactions.json`, `uploads.json`), картинки — в `img/`, тексты для цитат — в `quotes/`.

## Структура проекта

```
bot.py                     — точка входа (python bot.py)
tests/                     — тесты (python -m pytest), см. «Тесты»
sakuya_bot/
  config.py                — секреты из .env и пути к папкам
  logs.py                  — логирование
  storage.py               — чтение и запись data/*.json, картинки в img/ и проверка их размера
  replies.py               — скрытые ответы на команды; длинные списки — несколькими сообщениями
  modlog.py                — канал логов для модераторов
  checks.py                — кто управляет ботом (роль из настроек или «Управлять сервером»), права бота в канале
  settings/
    model.py               — настройки сервера: чтение и проверка settings.toml, шаблон файла
    __init__.py            — действующие настройки (current()) и файл data/settings.toml
    cog.py                 — команды /settings и слежение за файлом
  client.py                — класс бота: подключает функции, общие события и ошибки, heartbeat
  schedules/
    rules.py               — когда отправлять расписание, разбор даты и времени, описание словами
    cog.py                 — команды /schedule и цикл отправки картинок
  reactions/
    matching.py            — поиск слова в тексте (формы слов, точное слово, часть слова)
    emojis.py              — разбор поля emoji: один или несколько эмодзи по порядку
    cog.py                 — команды /reaction, реакции и ответы картинками на сообщения
  imaging/                 — общее для команд с картинками
    template.py            — шаблон с вырезом, настройками и освещением; открытие и сохранение картинки
    media.py               — кадры из GIF и видео, сборка GIF под лимит размера
    effect.py              — описание эффекта (ImageEffect, с шаблоном или без) и запуск для картинки или анимации
    sources.py             — поиск картинки, гифки или видео в сообщениях и скачивание
    command.py             — сценарий команды: найти → скачать → обработать → ответить; проверка канала
  coffee/
    latte.py               — эффект «латте-арт» (Pillow + NumPy)
    cog.py                 — команда !кофе
  beer/
    effect.py              — эффект «картинка в бокале пива» (Pillow + NumPy)
    cog.py                 — команда !пиво
  distort/
    effect.py              — радиальное искажение: «рыбий глаз» и вдавливание к центру (NumPy)
    cog.py                 — команды !explode и !implode
  museum/
    effect.py              — картинка в раме музея целиком, без обрезки (Pillow)
    cog.py                 — команда !музей
  quotes/
    picker.py              — чтение текстов, выбор цитаты по границам предложений и оформление сообщения
    cog.py                 — команда !цитата
```

Каждая функция бота — отдельный ког (`cog.py`): в нём её команды, данные и события. Файлы `rules.py`, `matching.py`, `emojis.py`,
`latte.py`, `picker.py` и `effect.py` (у пива, искажений и музея) не зависят от Discord, их удобно проверять отдельно. Новая команда с картинкой — это папка
с эффектом (`ImageEffect`: как обработать один кадр; шаблон необязателен) и коротким `cog.py`, который вызывает `reply_with_effect`. Новая функция добавляется своей папкой с `cog.py`
и одной строкой `add_cog` в `client.py`.

## Тесты

Тесты лежат в `tests/` и проверяют бота без подключения к Discord: вместо него — подставные объекты
(`tests/fakes.py`: вызов команды, участник, канал, вложение, сообщение). Каждый тест работает в своей временной
папке, так что настоящие `data/`, `img/` и `logs/` не затрагиваются, а токен не нужен.

Запуск (на компьютере разработчика, на сервер с ботом тесты ставить не нужно):

```bash
.venv\Scripts\pip install -r requirements-dev.txt
```

```bash
.venv\Scripts\python -m pytest
```

Весь набор идёт около 20 секунд. Без долгих тестов обработки видео: `python -m pytest -m "not slow"`;
один файл: `python -m pytest tests/test_emojis.py`; подробно, с именами тестов: `python -m pytest -v`.

| Файл | Что проверяет |
|---|---|
| `test_schedule_rules.py` | Когда отправлять расписание, догон после перезапуска, разбор дат и времени |
| `test_schedule_cog.py` | `/schedule`: создание, проверки картинки и прав бота, edit, pause, список, цикл отправки и ошибки |
| `test_reaction_cog.py` | `/reaction` и реакции на сообщения: комбинации эмодзи, кулдаун картинок, edit, pause, удаление картинок |
| `test_settings_model.py`, `test_settings_cog.py` | Файл настроек, `/settings`, защита от потери доступа, канал логов |
| `test_emojis.py`, `test_matching.py` | Разбор эмодзи и поиск слова в сообщении |
| `test_quotes.py` | Деление на предложения, выбор цитаты, лимит 2000 символов |
| `test_effects.py` | Эффекты на картинках, GIF и видео: не падают, укладываются в лимит, берут начало длинных |
| `test_client.py` | Регистрация команд (в том числе длина описаний), ответы на ошибки, кулдаун и каналы развлекательных команд |

После изменений в коде запустите тесты: если какой-то упал, pytest покажет, какая проверка и с какими значениями.
Новая проверка — функция `test_…` в подходящем файле; примеры подставного Discord — в `test_schedule_cog.py`.
Тесты не заменяют ручную проверку в Discord полностью: они не видят, как выглядит картинка, и не знают о новых
ограничениях Discord, — но ловят большинство ошибок до установки на сервер.

Те же тесты запускает GitHub при каждом пуше (`.github/workflows/tests.yml`, вкладка **Actions** в репозитории):
у коммита появляется зелёная галочка или красный крестик. С крестиком обновление на сервер лучше не ставить —
нажмите на него, чтобы увидеть, какой тест упал. Запустить проверку вручную: Actions → «Тесты» → **Run workflow**.

## Логи

Бот пишет в лог каждое действие: запуск и переподключения, использованные команды (кто и с какими параметрами),
созданные и удалённые расписания и правила, отправленные картинки, поставленные реакции, ошибки и отказы в доступе.
Раз в час пишет «Бот работает» — если таких строк нет, бот завис или выключен.

Логи выводятся в консоль и в файл `logs/sakuya-bot.log` (до 4 файлов по 5 МБ, старые удаляются сами).
Время в логах — в часовом поясе `timezone` из настроек. Текст сообщений участников в лог не попадает.
